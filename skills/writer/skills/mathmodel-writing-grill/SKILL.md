# 数学建模论文用户决策十问

## 使命

本 Skill 是**面向用户的论文写作决策门禁**，不是 Agent 的论文自检清单。它读取论文材料只为定制问题，然后把论文主线、证据取舍、结论强度、验证边界、图表叙事、摘要重点和局限披露等决定交给用户明确回答。

本 Skill 通常由 `$mathmodel-writing` 在两个门禁位置调用：

1. **论证计划门禁**：`reports/PAPER_CONTENT_PLAN.md` 完成后、正式撰写正文前；
2. **正文成稿门禁**：各问题章节、摘要和结论完成后、执行最终润色和交付前。

每个门禁都必须向用户一次性提出**恰好 10 个必须回答的问题**。完整写作流程会执行两次独立十问，共 20 个用户回答。它不重新建模，不生成新实验结果，不编造引用，也不替代 `$mathmodel-verification`。

## 输入与落盘

把用户明确指定的任务目录作为 `<WORK_ROOT>`；若用户未指定，则使用当前工作目录。

按实际存在情况读取：

- 题面和提交要求；
- `<WORK_ROOT>/reports/ANALYSIS_MODELING_REPORT.md`；
- `<WORK_ROOT>/reports/RESULTS_REPORT.md`；
- `<WORK_ROOT>/reports/PAPER_CONTENT_PLAN.md`；
- `<WORK_ROOT>/reports/LITERATURE_REPORT.md`；
- `<WORK_ROOT>/reports/DRAWIO_REPORT.md`；
- `<WORK_ROOT>/results/`、`<WORK_ROOT>/figures/`；
- `<WORK_ROOT>/paper/` 中当前引擎对应的正文、摘要和参考文献文件。

必须创建或更新：

- `<WORK_ROOT>/reports/PAPER_GRILL_REPORT.md`：分别记录两个门禁的 10 个问题、用户回答、写作决定、证据缺口和剩余风险；
- `<WORK_ROOT>/reports/PAPER_CONTENT_PLAN.md`：把已确认的论点、证据、章节和结论强度写回内容矩阵；
- `<WORK_ROOT>/reports/paper_evidence_map.json`：检查并更新 claim 到 artifact/citation 的映射；证据必须包含版本和 content hash，任何 stale 依赖都会使 claim 变为 stale；
- 已存在的论文草稿：仅在用户回答已经解决具体写作决定时更新对应章节。

使用 [REPORT-FORMAT.md](references/REPORT-FORMAT.md) 记录访谈。每个门禁构造问题时读取 [QUESTION-DIMENSIONS.md](references/QUESTION-DIMENSIONS.md)，结合当前题目和论文状态生成本门禁专属的 10 个问题。

## 判定当前门禁

- `PAPER_CONTENT_PLAN.md` 已存在，而主要问题章节尚未完成：进入**论证计划门禁**。
- 主要问题章节已完成并包含真实结果：进入**正文成稿门禁**。
- 两者均不满足：先指出缺少的前置产物，不用十问代替写作阶段本应完成的工作。

## 提问前允许做的事

只进行定制问题所需的最小读取：

1. 从题面确认实际问题清单，核对摘要、内容计划和正文入口的问题集合。
2. 识别会改变论文主线、篇幅分配、结论强度、图表取舍或局限披露的用户决策点。
3. 区分“文件中已有答案的事实”与“必须由用户表达的写作选择”。
4. 读取问题维度，用已知事实作为问题背景，而不是替用户作出决定。

不得在提问前自行修正文稿、决定论文主线、替用户选择结论强度或输出内部审查结论。即使 Agent 认为论文没有问题，也不能跳过、减少或自动通过十问。

## 强制十问协议

- 论证计划门禁和正文成稿门禁各进行一轮首次访谈；每轮一次性提出恰好 10 个编号问题，编号固定为 1–10。
- 每题必须针对当前题目、内容计划或正文草稿，要求用户表达判断、偏好、取舍或约束。
- 每题说明“为什么要问”或“答案会影响什么”。
- 可以给互斥选项帮助理解，但不得推荐、预选或暗示默认答案。
- 用户可以回答“不确定”，但仍必须对该编号作出显式回复。
- 要求用户按 1–10 逐题回答；不接受“你自己检查”“你看着办”“全部按推荐”或类似授权作为完整回答。
- 发出十问后立即暂停。在收到本门禁全部 10 项回答前，不得继续写正文、修改论文、润色、编译、导出或验收。

问题格式：

```markdown
## 论文写作决策十问 · 论证计划门禁

请按 1–10 逐题回答；暂时无法决定的题可以写“不确定”，但请不要省略编号。

1. <具体问题>
   为什么要问：<会影响的论点、证据、章节、图表或结论强度>
...
10. <具体问题>
    为什么要问：<影响>
```

## 明确禁止

- 禁止 Agent 在提问后模拟、推测或代替用户回答。
- 禁止把十问只放在内部推理、报告或检查清单中而不展示给用户。
- 禁止先自行审查或修改论文，再用十问确认 Agent 已经做出的决定。
- 禁止因为材料齐全、结论明显或时间紧张而少问、跳过或自动通过。
- 禁止给出 10 个推荐答案后让用户整体接受。
- 禁止把数字核对、引用存在性、编译和排版检查伪装成用户决策问题。

## 每轮回答后的处理

收到回复后，按顺序执行：

1. 检查编号 1–10；若有缺答或用笼统授权代替回答，只列出缺失、含糊的编号并继续等待，不得自行补齐。
2. 十项齐全后，简洁复述用户的明确决定，并单独标记回答为“不确定”的项目。
3. 将回答与题面、真实结果和已核验文献交叉核对；若发生冲突，指出具体编号并只重新询问相关编号，不得替用户裁决。
4. 更新 `PAPER_GRILL_REPORT.md`、`PAPER_CONTENT_PLAN.md` 和证据映射。
5. 只有全部编号完成且冲突得到处理后，才把用户决定交回 `$mathmodel-writing` 写入相应章节。

遇到 `EVIDENCE_GAP` 时只能选择以下处理：

- 返回编码或实验阶段补充真实证据；
- 删除无证据论点；
- 明确写入局限并降低结论强度。

不得用示例数值、模型记忆、未经核验的文献或泛化的“结果表明”补洞。

## 与论文验收的边界

本 Skill 只采集需要用户判断的论文决策，例如：

- 哪个结果应作为论文主线；
- 多个模型如何取舍和解释；
- 证据不足时结论应降低到什么程度；
- 哪些局限必须主动披露；
- 摘要应突出哪些可追溯结果。

以下 Agent 检查必须交给 `$mathmodel-verification`，不得由本 Skill 在内部自问自答：

- 编译是否成功；
- 引用的文件、图表和章节是否存在；
- 占位符、内部路径和身份信息扫描；
- 最终 PDF、DOCX、OMML 和页面视觉质量检查。

## 完成条件

每个门禁只有在用户对 1–10 全部给出显式回答、冲突已处理且回答已落盘后才能完成。完成时输出：

- 已确认的论文主线与逐问结论；
- 已更新的内容计划、正文位置和质询报告；
- 仍存在的证据缺口、降级结论和退回任务；
- 当前门禁状态：READY、READY_WITH_RISKS 或 BLOCKED；任何缺答都必须是 BLOCKED。

回答为“不确定”的项目必须留在 `PAPER_GRILL_REPORT.md` 和 `PAPER_CONTENT_PLAN.md` 中，并在写作中采用保守表述或退回相应阶段；不得把“不确定”改写成用户已经确认。
