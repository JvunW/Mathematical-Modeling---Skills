# 数学建模方案质询

## 使命

在建模方案交给代码阶段之前，依据题面、附件数据和现有建模报告进行批量压力测试。只把必须由用户或领域专家决定的高影响不确定性拿出来询问；能够从材料、数据或已有计算中确认的事实应自行核对。

本 Skill 通常承接 `$mathmodel-analysis`，并在生成最终“代码实现任务清单”前运行。它不替代赛题分析，不编写求解代码，也不使用软件项目中的 `CONTEXT.md` 或 ADR。

## 输入与落盘

把用户明确指定的任务目录作为 `<WORK_ROOT>`；若用户未指定，则使用当前工作目录。

优先读取：

- 题面及全部附件说明；
- `<WORK_ROOT>/plan.md`；
- `<WORK_ROOT>/reports/ANALYSIS_MODELING_REPORT.md`；
- 数据字典、EDA 记录和能够解释字段口径的文件；
- 已存在且与模型可实现性直接相关的代码、配置或测试。

必须创建或更新：

- `<WORK_ROOT>/reports/MODEL_GRILL_REPORT.md`：记录问题、用户回答、最终决策、矛盾和剩余风险；
- `<WORK_ROOT>/reports/ANALYSIS_MODELING_REPORT.md`：把已确认的决定写回对应的题意解释、假设、变量、公式、约束、求解或验证小节。
- `<WORK_ROOT>/reports/model_manifest.json`：同步回写已确认的假设、风险、目标、约束和验证计划；每次修改保持 schema 1.0 有效，不只更新 Markdown 报告。

使用 [REPORT-FORMAT.md](references/REPORT-FORMAT.md) 记录质询过程。需要构造问题时读取 [QUESTION-DIMENSIONS.md](references/QUESTION-DIMENSIONS.md)，只选择与当前赛题相关的维度。

## 提问前核对

在第一轮之前完成以下工作：

1. 核对题面实际顶层问题数量及问题间依赖，不能从模板推断问题数量。
2. 核对附件字段、单位、缺失值、异常值、时间范围和样本粒度。
3. 检查模型初稿是否已经给出变量、假设、目标函数、约束、算法和验证方案。
4. 对可从题面、数据或简单验算确定的问题自行作答，不占用用户问题名额。
5. 标记会改变模型结构、结果解释或代码接口的高影响未知项。

如果不存在高影响未知项，不要为了凑数提问；记录“无需用户决策”，完成一致性检查后结束。

## 批量质询协议

- 总共进行 1 至 3 轮；高影响不确定性已经消除时提前结束。
- 每轮最多 10 个编号问题。
- 第一轮原则上提出 10 个问题；探索后不足 10 个实质问题时只问实际存在的问题。
- 第二、三轮只追问尚未解决的高影响问题，不重复已确认内容。
- 每个问题必须说明它影响什么，并给出一个推荐答案及简短理由。
- 问题应能直接改变模型、实现口径或验证方案，避免开放式闲聊。
- 一次发出整批问题，等待用户整批回复后再继续。

问题格式：

```markdown
建模方案质询 · Round 1 of 3

1. <具体问题>
   影响：<模型、数据、实现或验证影响>
   推荐答案：<推荐选择及理由>
```

允许用户回复“全部采用推荐答案”，但若推荐答案之间或与用户补充条件冲突，必须先指出冲突，不能直接收口。

## 每轮回答后的处理

收到整批回答后，按顺序执行：

1. 汇总已确认的解释、假设和模型决定。
2. 将用户回答与题面、数据和现有公式交叉核对。
3. 明确指出互相冲突、无法计算或会使后续问题失去边际效果的决定。
4. 更新 `MODEL_GRILL_REPORT.md`。
5. 把已解决内容写回 `ANALYSIS_MODELING_REPORT.md`，不能只保留在聊天记录中。
6. 判断是否仍存在会改变模型结构、代码接口或结果可信度的问题。

如果回答意味着需要新的数据、重新清洗或额外实验，应记录具体缺口和替代方案，不得编造数据补齐。

## 重点一致性门禁

结束前至少确认：

- 题意解释不会让后续新增条件失去作用；
- 同一变量、符号、单位和时间粒度在各子问题中一致；
- 目标函数与题目评价标准对应，硬约束和软约束没有混用；
- 所选模型能够由现有数据识别并在竞赛时间内求解；
- 训练、验证和外部变量使用不存在未来信息泄漏；
- 验证方法与模型类型和结论风险匹配；
- 每个子问题的输入、输出和依赖关系足够明确，可以交给编码阶段。

## 停止与最终输出

出现以下任一条件时停止提问：

- 高影响未知项已经解决；
- 剩余问题只影响局部实现细节；
- 已完成第三轮。

停止时输出：

- 已确认的关键决定；
- 对 `ANALYSIS_MODELING_REPORT.md` 和 `MODEL_GRILL_REPORT.md` 的更新；
- 仍需在编码或实验阶段验证的风险；
- 是否允许生成最终代码实现任务清单。

第三轮后仍未解决的问题必须作为显式风险和备选方案保留，不得继续无限追问，也不得伪装成已经确定。
