# 中文论文润色的保护内容

## 使用时机

每次调用 `$mathmodel-humanizer-zh` 都必须先读取本文件。保护规则优先于语言风格规则；发生冲突时保留原文。

## 不可变内容

正文起草和成稿润色都必须保持：

- 数值、正负号、小数位、百分比、科学计数法、样本量和时间范围；
- 单位、量纲、阈值、权重、排名、误差和置信区间；
- 变量名、下标、公式、数学环境、公式编号和公式引用；
- 图、表、章节、附录的编号、标签、路径和交叉引用；
- 文献键、作者、年份、DOI、引用编号及其支持的相邻论点；
- Typst/LaTeX/Markdown 命令、代码块、图片路径和模板控制语句；
- 模型名称、算法名称、参数、目标函数、约束和停止条件；
- 否定、条件、因果/相关关系、结论强度、适用边界、不确定性和局限；
- 比赛要求的 AI 使用披露、人工核验记录和责任说明。

可以调整引用所在句子的措辞，但不得让引用离开它所支持的论点，也不得把一个引用移动到它未支持的新判断后。

## 源文件保护

- Typst：保护 `$...$`、标签、引用、函数调用、模板设置、`#image(...)` 和 include 路径。
- LaTeX：保护数学环境、命令、`\label`、`\ref`、`\cite`、`\includegraphics`、bibliography 和代码环境。
- Markdown：保护数学分隔符、代码围栏、图片链接、引用键、HTML 块及导出所需标记。

不得直接在 PDF 上覆盖文字。Word 路线优先润色用于导出的 Markdown，再重新生成 DOCX；只有用户明确要求且不存在可靠源文件时才直接编辑 DOCX，并保留修订前副本。

## 两种模式的检查方式

正文起草模式面对全新章节时没有可靠的“修改前”文本，不得为了生成通过报告而构造虚假基线。此时逐节对照 `results_manifest.json`、`paper_evidence_map.json` 和术语表，记录人工证据核对结果。若正文起草模式改写了已有段落，则把原段落或源文件作为基线并运行自动比较。

成稿润色模式必须对每个修改文件运行自动比较：

```text
python "<SKILL_DIR>/scripts/check_protected_content.py" "<BEFORE_FILE>" "<AFTER_FILE>" --json "<REPORT_JSON>"
```

返回码：

- `0`：脚本覆盖的保护 token 未变化；
- `1`：检测到新增、删除或替换，必须修复并重跑；
- `2`：文件或编码错误，检查未完成，不能继续交付。

脚本比较数字、数值单位组合、数学片段、引用、标签/交叉引用、图片路径、LaTeX 命令和代码块。它不能证明语义等价，因此还必须人工核对以下项目：

- “不显著”是否被误写成“显著”；
- “相关”是否被误写成“导致”；
- “在给定假设下”是否被省略；
- 适用范围、置信程度和局限是否减弱；
- 失败实验、负面结果和异常情况是否仍被披露；
- AI 使用说明是否仍真实、完整且位于要求位置。

## 失败处理

检查失败时，不对整个文件做无依据的覆盖。根据 `<WORK_ROOT>/state/humanization/` 中的快照恢复受影响的保护内容或段落，保留可以证明安全的语言修改，再重新运行比较器。所有失败和修复写入 `reports/HUMANIZATION_REPORT.md`。
